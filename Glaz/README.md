# Glaz (Eye)

Проект для определения объектов на экране.

## Описание

Этот проект предназначен для автоматического обнаружения и распознавания объектов, отображаемых на экране устройства. Основная цель - предоставить инструменты для анализа визуального содержимого экрана в реальном времени или по изображениям.

## Функциональность

- **Захват скриншотов**: Возможность захвата и отображения скриншотов выбранного монитора
- **Выбор монитора**: Поддержка множественных мониторов с возможностью выбора
- **GUI интерфейс**: Удобный графический интерфейс на базе Tkinter
- Обнаружение объектов на скриншотах экрана (планируется)
- Реальное время анализа содержимого экрана (планируется)
- Поддержка различных типов объектов (планируется)
- Интеграция с компьютерным зрением (планируется)

## Технологии

- **Python 3.8+**
- **Tkinter** - для графического интерфейса
- **MSS (MSSS)** - для захвата скриншотов
- **Pillow (PIL)** - для обработки изображений

## Установка

1. Установите Python 3.8 или выше
2. Установите зависимости:
```bash
pip install -r requirements.txt
```

## Использование

Запустите программу:
```bash
python main.py
```

### Интерфейс программы:
1. Выберите монитор из выпадающего списка
2. Нажмите "Захватить экран" для начала отображения скриншотов
3. Используйте полосу прокрутки для навигации по изображению
4. Нажмите "Остановить" для прекращения захвата
5. **Область ошибок**: все сообщения и ошибки отображаются в выделяемой текстовой области с прокруткой
   - Текст можно выделять и копировать (Ctrl+C)
   - Нажмите "Очистить" для очистки области ошибок
   - Автоматически ограничивается до 100 последних сообщений

## Алгоритм определения объектов

### Этап 1: Обнаружение объектов на экране
1. Захватывается скриншот монитора
2. Применяется детекция пиков (`detect_color_peaks`) — находятся резкие переходы цвета
3. На изображении пиков ищутся связные области по сплошным линиям (`detect_objects_by_lines`) — горизонталь, вертикаль, диагонали
4. Каждая связная область становится объектом с `bbox` и `center_peaks`

### Этап 2: Наведение курсора на объект
1. Проверяется, попадает ли курсор в `bbox` какого-либо объекта
2. При первом входе на объект:
   - Запоминается текущая позиция курсора
   - Начинается отслеживание стабильности (ждём пока пользователь перестанет двигать мышь)
   - Вычисляется оптимальный масштаб лупы для вписки объекта в большой круг

### Этап 3: Ожидание остановки мыши
1. Если курсор двигается — таймер стабильности сбрасывается
2. Если курсор не двигался **0.15 сек** — переход к следующему этапу

### Этап 4: Центрирование курсора
1. Курсор принудительно перемещается в **центр масс объекта** (на сканируемом мониторе)
2. Устанавливается **блокировка курсора** — пользователь не может сдвинуть мышь
3. Запускается таймер ожидания перед снятием подписи (**0.3 сек**)

### Этап 5: Масштабирование объекта и формирование изображения пиков
1. Вычисляется размер объекта в исходных координатах
2. Рассчитывается `loupe_size_effective` по формуле:
   ```
   size = 50 × (max(width, height) / 2) / r_large
   ```
   где `r_large = 12 × √2 ≈ 17 px` — радиус большого круга
3. Лупа вырезает область `size × size` пикселей и масштабирует до **50×50**:
   - `size > 50` → отдаление (объект больше круга)
   - `size < 50` → приближение (объект меньше круга)
   - `size = 50` → без масштабирования
4. К масштабированному фрагменту применяется `detect_color_peaks` — создаётся изображение пиков

### Этап 6: Анализ геометрии и зажигание сегментов
1. На изображении пиков лупы анализируются **56 сегментов** геометрии:
   - 20 сегментов перекрестия (по 5 на каждое направление)
   - 8 сегментов квадрата 12×12
   - 8 сегментов квадрата 24×24
   - 4 сегмента ромба
   - 8 дуг малого круга (r = 6√2)
   - 8 дуг большого круга (r = 12√2)
2. Для каждого сегмента:
   - Получаются пиксели вдоль линии/дуги (алгоритм Брезенхема)
   - Проверяется наличие **≥3 подряд чёрных пикселей** (пиков)
   - Если есть → сегмент "загорается" **красным**
   - Если нет → сегмент остаётся **синим**

### Этап 7: Формирование подписи и поиск в базе данных
1. Индексы всех "загоревшихся" сегментов собираются в **отсортированный кортеж** — подпись объекта
2. Подпись сравнивается с существующими в БД (fuzzy matching, допуск до 2 сегментов)
3. Результат:
   - **Найдено совпадение** → объект знакомый, выводится его ID
   - **Не найдено** → новый объект, присваивается новый ID, подпись сохраняется в БД

### Этап 8: Завершение
1. Сохраняется скриншот лупы (если включена галочка)
2. Снимается блокировка курсора
3. Устанавливается флаг — повторное определение не запустится пока курсор не уйдёт с объекта
